内嵌封面
音视频参数怎么看
1. 先分层次：容器 ≠ 编码
 
容器 / 封装层 / 轨道 / 编码 / 原始信号，五层从上到下
容器和编码是两回事：MP4 里可以装 H.264，也可以装 H.265；反过来同一个 AAC 音轨，装进 MP4、MKV、TS 都行。看参数前先分清「这是容器属性还是编码属性」。
2. 视频关键参数
维度常见取值要点
编码标准H.264/AVC、H.265/HEVC、AV1、VP9、MPEG-2、ProRes定压缩率、兼容性、硬解支持
分辨率1920×1080、3840×2160；SAR / PAR / DAR像素不等于显示，注意旋转与宽高比
帧率 fps23.976 / 24 / 25 / 29.97 / 30 / 50 / 60，CFR 与 VFR时基 timebase 决定时间戳精度
色深8 / 10 / 12 bit10bit 是 HDR 与高画质的基础
色度采样4:2:0 / 4:2:2 / 4:4:44:2:0 最省，4:4:4 保色度，用于后期
色彩空间BT.601 / 709 / 2020；primaries · transfer · matrix三要素缺一会偏色，错配很常见
HDRHLG、PQ / HDR10、HDR10+、Dolby Vision需色深 + 传输函数 + 元数据配套
扫描方式Progressive、Interlaced（TFF / BFF）交错源要正确去交错，否则拉丝
Profile / LevelHigh@4.1、Main10@5.1决定设备能否硬解，Level 限上界
GOP 结构I / P / B 帧、keyint、IDR、闭合与开放 GOP影响拖动响应与直播延迟
码率控制CBR / VBR / CRF / ABR；maxrate · bufsize（VBV）CRF 控质量，VBV 控网络抖动
质量评价PSNR / SSIM / VMAFVMAF 最贴近主观，PSNR 只作参考
码流格式Annex-B 起始码 vs AVCC / HVCC 长度前缀封装进 MP4 要转 AVCC，否则难播
3. 音频关键参数
维度常见取值要点
编码格式AAC-LC、HE-AAC、Opus、MP3、FLAC、ALAC、AC-3、DTS有损看场景，无损用于归档与母版
采样率8k / 16k / 44.1k / 48k / 96k / 192k Hz影视配音通常 48k，音乐常见 44.1k
位深16 / 24 / 32 bit，int 与 float制作链路 24bit，交付常 16bit
声道与布局mono、stereo、5.1、7.1；L R C LFE Ls Rs布局标错会串声道，例如人声跑后置
码率64–320 kbps；每声道约 64k 起步VBR 更省，CBR 利于流媒体稳定
AAC 档次LC / HE / HEv2 / ELD；ADTS 与 raw（LATM）MP4 内是 raw AAC，裸流才是 ADTS
帧长AAC 1024（960）样本；Opus 2.5–60 ms直接决定延迟与封装对齐
采样格式S16 / S24 / S32 / F32；planar 与 interleavedplanar 便于处理，interleaved 便于输出
响度LUFS（EBU R128）、True Peak流媒体常以 -14 LUFS、TP -1 dBTP 为目标
唇音同步A/V offset、delay、时间戳偏移音画不同步多半是时间戳或 delay 问题
字幕SRT / ASS / WebVTT / PGS；default 与 forcedforced 只在外语片段强制显示
4. GOP 与 I / P / B 帧：为什么解码顺序 ≠ 显示顺序
 
I 独立解码 · P 参考前序帧 · B 双向参考须等后序帧，故解码顺序与显示顺序不同
B 帧要参考「后面的帧」才能解码，所以必须先解出它后面的 P 帧。这就是容器里同时存在 PTS（什么时候显示）和 DTS（什么时候解码）两个时间戳的唯一原因。
5. 读一份报告的建议顺序
  1. 容器 + 编码组合 —— 先确认目标设备 / 浏览器是否支持
  2. 分辨率 + 帧率 + 扫描方式 —— Progressive 还是 Interlaced
  3. 色深 + 色度采样 + 色彩三要素 —— 会不会偏色、够不够格播 HDR
  4. Profile@Level —— 硬解能力上限
  5. 视频码率 + 音频码率 —— 配合分辨率看 bpp 才有意义
  6. 音轨：编码 + 采样率 + 声道布局 —— 布局写错人会声跑到后置
  7. GOP / 关键帧间隔 —— 影响拖动响应、seek 精度与直播延迟
  8. 时长 + 总大小 + 各轨语言 / default / forced
 三个高频坑： ① 以为「MP4 播不了」是编码问题，其实是 moov 在文件尾部（没做 faststart），或码流是 Annex-B 没转 AVCC； ② 画面发灰 / 过艳：primaries / transfer / matrix 三者只标一个或标错，尤其 BT.601 与 BT.709 混用； ③ 音画不同步、声道错位：多半是容器时间戳或音轨 delay，而不是「编码坏了」。
